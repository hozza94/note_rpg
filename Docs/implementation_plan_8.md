# 구현 계획 8: 순례자 스킬트리 확장 & 보스 전용 스킬 설계

## 1. 순례자 스킬트리 노드 확장 (데이터 반영)

### 1.1 추가된 분기(요약)
| 구역 | 노드 수 | 역할 |
|------|--------|------|
| 수양의 길 | 4 | 시작점에서 좌하 방향, 생존·신앙·받피감 키스톤 |
| 예언의 가지 | 3 | `pilgrim_faith_2`에서 분기, 치명 위주 |
| 전장의 측면 | 2 | `pilgrim_atk_2`에서 분기, 공격·속도 |
| 방패선 | 2 | `pilgrim_def_1`에서 분기, HP·방어 |
| 질주선 | 2 | `pilgrim_spd_1`에서 분기, PP·회피 |
| 천상 상승 | 2 | `pilgrim_zeal_2`에서 상승, 피해량 키스톤 |
| 심연 저항 | 2 | `pilgrim_resolve_2`에서 분기, 저HP 피해·체력 |

### 1.2 밸런스·호환
- 기존 세이브: `unlockedSkillNodes`에 새 ID가 없으면 그대로 동작.
- `damageMul` / `damageTakenMul` / `lowHpDamageMul`는 기존 로직대로 **곱연산** 누적.
- 총 노드 수가 늘어나 레벨업 포인트 대비 트리 완성 난이도는 상승 → **향후** 지역·퀘스트로 추가 포인트를 줄지 별도 검토.

## 2. 보스 전용 스킬 — 설계 방향 (계획만, 미구현)

### 2.1 목표
- 일반 몬스터와 **동일 스킬 풀을 재사용**하면 보스전이 단조로워짐.
- **등급 C 이상 보스** 또는 **지역 보스 전용**으로 시각·기믹이 분명한 스킬을 두어, `skills` 데이터와 전투 AI에서만 사용.

### 2.2 데이터 스키마(안)
```text
GAME_DATA.skills.<id>: {
  name, cost?, type, effect, desc,
  bossOnly?: true,           // 플레이어·일반 몬스터 스킬 목록에서 제외
  minGrade?: 'C' | 'B' | 'A', // 몬스터 등급 하한 (선택)
  tags?: ['phase', 'aoe']   // 연출·AI 분류용 (선택)
}
```

- `monsters[].skills`에는 기존처럼 문자열 ID만 나열.
- 플레이어 `unlockSkillNode` / `activeSkillIds` 동기화 시 **`bossOnly` 스킬은 필터**하여 절대 배우지 못하게 함.

### 2.3 구현 시 건드릴 코드(후속 작업)
| 영역 | 내용 |
|------|------|
| `data.js` | 보스 전용 스킬 ID 추가, 보스 `monster.skills`에만 배치 |
| `game.js` | `syncUnlockedActiveSkills`, 스킬 메뉴 UI, 자동전투 AI에서 `bossOnly` 제외 |
| 전투 | `useSkill` / 몬스터 턴: 보스는 쿨다운·페이즈·HP%에 따라 전용 스킬 우선 선택 (간단한 룰부터) |
| 연출 | 보스명 + 스킬명 로그, 필요 시 전용 이펙트 플래그 |

### 2.4 스킬 아이디어 (예시 — 이름만)
| 보스 | 컨셉 | 효과 방향 |
|------|------|-----------|
| 원혼 (`wraith`) | 영혼 분리 | 다중 타격 또는 공포 + 자가 버프 |
| 진흙 거인 (`mud_giant`) | 대지 격동 | 광역 물리·방어 디버프 |
| 석화 세라프 (`stone_seraph`) | 석화·빛 | 속도/행동 제한 + 강한 일격 |

실제 수치·`effect` 키는 전투 밸런스 확정 후 `data.js`에 반영.

### 2.5 검증 체크리스트 (구현 후)
- [ ] 플레이어가 보스 전용 스킬을 스킬트리·액티브 목록에 넣을 수 없다.
- [ ] 일반 몬스터는 기존 스킬만 사용한다.
- [ ] 지정 보스만 새 ID를 `skills` 배열에 포함한다.
- [ ] 저장/로드 후에도 동일하게 동작한다.
