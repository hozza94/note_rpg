# implementation_plan_12: 보스 던전/보스 리스트 + 보스 전용 레어 드랍 설계

## 1) 배경
- 현재 보스전은 `현재 지역 보스 1회 도전` 흐름에 가깝고, 이전 지역 보스 재도전 동선이 약하다.
- 보스 고유 보상을 파밍하는 루프가 없어, 중후반 파밍 동기가 일반 필드 드랍에 치우친다.

## 2) 목표
- 이전 지역 보스를 포함한 **보스 리스트(보스 던전)**를 제공한다.
- 보스에게서만 획득 가능한 **전용 레어 아이템** 획득 기회를 만든다.
- 기존 지역 진행(탐험도 100% -> 보스 클리어 -> 다음 지역)과 충돌 없이 공존시킨다.

## 3) 핵심 UX
- 하단 액션에 `보스던전` 버튼 추가.
- 클릭 시 `보스 던전 모달` 오픈:
  - 보스 카드 목록: 이름, 지역, 권장 레벨, 최초 클리어 여부, 최근 클리어 시간.
  - 필터: `전체 / 클리어 완료 / 미클리어 / 현재 지역`.
  - 정렬: 지역 순(기본), 레벨 순.
- 카드 액션:
  - `도전`: 즉시 해당 보스전 시작
  - `드랍 보기`: 전용 드랍/확률 안내
- 진행 보스(기존 `bossChallenge`)는 유지하고, 별도 파밍 동선으로 보스 던전 제공.

## 4) 데이터 설계
### 4-1. `js/data.js`
- `bossDungeon` 블록 추가:
  - `entries`: `{ bossId, regionId, recommendedLv, unlockType }[]`
  - `unlockType`:
    - `region_reached`: 해당 지역 도달 시 해금
    - `boss_cleared`: 해당 보스 최초 클리어 시 해금(확장용)
- `bossExclusiveDropTables` 추가:
  - 키: `bossId`
  - 값: `[{ itemId, chance, minQty?, maxQty? }]`
- 아이템은 기존 `items`에 신규 레어 장비/재료를 정의하고, 일반 `dropTables`에는 넣지 않는다.

### 4-2. 상태(`game.js` state) 확장
- `state.world`:
  - `bossDungeonUnlocked: { [bossId]: true }`
  - `bossClearHistory: { [bossId]: { clearCount, lastClearAt, bestTurn? } }`
  - `bossDropPity: { [bossId]: number }` (레어 미획득 누적 카운트)

## 5) 전투/보상 규칙
### 5-1. 도전 규칙
- 보스 던전에서 선택한 보스는 `startBattle` 시 `battle.source = "boss_dungeon"` 플래그 부여.
- 기존 지역 진행 보스전은 `battle.source = "region_progress"`로 구분.

### 5-2. 드랍 규칙 (보스 전용 레어)
- 승리 시 기본 드랍(`dropTableId`) + 보스 전용 드랍(`bossExclusiveDropTables[bossId]`) 판정.
- 전용 드랍은 낮은 확률(예: 2~8%)로 시작.
- 연속 미획득 완충:
  - `bossDropPity[bossId]` 누적치에 따라 확률 소폭 증가.
  - 레어 획득 시 해당 보스 pity 초기화.
- 최초 클리어 보상:
  - 전용 토큰/재화 1회 확정 지급(중복 파밍 억제 + 첫 클리어 성취감 확보).

## 6) 해금 정책
- 기본 정책(1차): `현재 지역 이상 도달` 시 이전 보스 포함 모두 선택 가능.
- 즉, 지역 이동만 했어도 과거 보스 재도전 가능.
- 확장 정책(2차): 특정 보스 클리어 시 상위 보스 던전 난이도 해금.

## 7) 밸런스 원칙
- 보스 전용 레어는 **체감 강하지만 필수는 아닌** 수치로 설정.
- 슬롯별 파워 상한을 지역 단계별로 제한:
  - 이전 지역 보스 레어는 현지역 일반 파밍과 동급~약간 상위.
  - 현지역 보스 레어가 다음 지역 진입 체감 보너스를 제공.
- 동일 보스 파밍 루프 과열 방지:
  - 골드/경험치는 기존과 동일 또는 소폭 감쇠(던전 재도전은 레어 목적 중심).

## 8) UI/구현 범위 (1차)
- `index.html`
  - `보스던전` 버튼 추가
  - 보스 던전 모달 마크업 추가(목록/필터/드랍 보기 영역)
- `style.css`
  - 보스 카드 리스트, 난이도 배지, 클리어 상태 뱃지 스타일
- `game.js`
  - 보스 던전 모달 오픈/닫기
  - 필터/정렬 렌더링
  - 보스 선택 도전 시작
- `js/engine/battle.js`
  - 승리 처리에 전용 드랍 + pity 로직 추가
- `js/data.js`
  - 보스 전용 드랍 테이블/신규 레어 아이템 정의

## 9) 리스크 및 대응
- 리스크: 보스 파밍이 일반 필드 가치를 압도할 수 있음.
  - 대응: 전용 레어는 저확률 + pity 완충 + 과도한 스탯 금지.
- 리스크: 상태 필드 증가로 세이브 호환 이슈.
  - 대응: 로드 시 기본값 주입(누락 필드는 빈 객체로 초기화).
- 리스크: UI 복잡도 증가.
  - 대응: 1차는 최소 기능(목록/도전/드랍 보기)만 제공.

## 10) 단계별 적용 순서
1. 데이터 구조 추가 (`bossDungeon`, `bossExclusiveDropTables`, 신규 아이템)
2. 상태 초기화/세이브 호환 필드 추가
3. 보스 던전 모달 UI 및 진입/도전 연결
4. 전용 드랍 + pity 로직 연결
5. 밸런스 수치 조정 및 수동 테스트

## 11) 수동 검증 시나리오
1. 현재 지역 진입 후 보스 던전 목록에 이전 보스가 노출되는지 확인
2. 보스 던전에서 과거 보스 선택 전투 진입 확인
3. 보스 승리 시 기본 드랍과 전용 드랍이 함께 판정되는지 확인
4. 레어 미획득 누적 후 재도전 시 pity 반영으로 획득 확률이 체감 상승하는지 확인
5. 저장/불러오기 후 `bossClearHistory`, `bossDropPity` 값이 유지되는지 확인
