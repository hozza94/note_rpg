# 배포 준비 계획서 1

본 문서는 `note_rpg`를 다수 사용자 대상으로 배포하기 위한 준비 항목을 정리한다.  
목표는 "기능 추가"보다 "안정 운영 가능한 구조"를 먼저 갖추는 것이다.

---

## 1. 목표와 기준

### 목표

- 다수 동시 접속 상황에서도 저장/로드/전투/재화 흐름이 안정적으로 동작한다.
- 장애 발생 시 빠르게 탐지하고 복구할 수 있다.
- 업데이트 시 기존 유저 데이터가 깨지지 않는다.

### 오픈 최소 기준 (MVP)

- 계정 로그인, 저장/로드, 기본 플레이 루프가 서버 기준으로 동작
- 에러 추적, 서버 로그, 기본 모니터링 활성화
- 데이터 마이그레이션 정책 존재
- 스테이징에서 사전 검증 완료

---

## 2. 현재 상태 가정

- 프론트 중심 구조에서 점진적으로 모듈화 진행 중 (`js/engine/*`)
- 데이터 규칙 검증 스크립트 보유 (`scripts/validate-game-data.mjs`)
- 데이터 파츠 라운드트립 검증 보유 (`scripts/verify-data-roundtrip.mjs`)
- 향후 대규모 배포를 위해 서버 권한 중심 구조로 전환 필요

---

## 3. 핵심 준비 영역

## 3.1 백엔드/데이터 저장 구조

- 유저, 인벤토리, 장비, 성물, 재화, 진행도 저장 스키마 설계
- 세이브 API 설계 (`save`, `load`, `sync`, `migrationVersion`)
- 데이터 정합성 규칙 정의 (예: 재화 음수 금지, 미보유 아이템 장착 금지)
- 서버 DB 백업/복구 정책 수립 (일/주 단위 스냅샷)

## 3.2 인증/보안

- 비밀번호 해시(단방향), 토큰 만료/재발급 적용
- 모든 통신 HTTPS 강제
- 입력 검증 및 API 레이트리밋 적용
- 서버 권한 검증(치트 방지): 핵심 보상 계산은 서버 기준 처리

## 3.3 운영 배포 체계 (CI/CD)

- 브랜치 전략 확정 (`main`/`develop` 또는 단일 배포 브랜치)
- 자동 테스트 + 빌드 + 스테이징 배포 파이프라인 구축
- 프로덕션 배포 롤백 절차 정의
- 릴리즈 노트 템플릿 통일

## 3.4 모니터링/관측성

- 프론트 에러 추적 (런타임 JS 에러)
- 백엔드 메트릭 (응답 시간, 에러율, DB 커넥션)
- 비즈니스 지표 (DAU, 잔존율, 재화 수급/소모, 가챠 사용량)
- 경보 규칙 설정 (에러율 급증, 저장 실패율 증가)

## 3.5 데이터 버전/마이그레이션

- 세이브 데이터 버전 필드 도입
- 버전별 마이그레이션 함수 분리
- 구버전 유저 로드 시 자동 변환 + 실패 시 안전 복구
- 마이그레이션 테스트 케이스 관리

## 3.6 성능/부하 대응

- 목표 동접 수치 정의 (예: 1,000 / 5,000 / 10,000)
- 부하 테스트 시나리오 작성 (로그인/저장/전투 반복)
- 캐시 전략 수립 (읽기 트래픽 분산)
- DB 인덱스/쿼리 병목 사전 점검

## 3.7 운영 도구

- 운영자용 계정/권한 분리
- 유저 상태 조회/보정(재화, 인벤토리, 진행도) 도구
- 공지/점검 모드/긴급 차단 기능
- 감사 로그(누가 무엇을 보정했는지) 기록

---

## 4. 단계별 실행 계획

| 단계 | 기간(권장) | 목표 | 완료 기준 |
|---|---:|---|---|
| 1단계: 기반 설계 | 1~2주 | 서버 저장 구조, 인증, 마이그레이션 정책 확정 | API/DB 설계 문서 승인 |
| 2단계: 서버 MVP | 2~4주 | 로그인/저장/로드 서버 연동 | 실제 계정 기반 저장/복원 동작 |
| 3단계: 운영 기초 | 1~2주 | 모니터링/로그/경보/백업 구축 | 장애 탐지 및 복구 절차 검증 |
| 4단계: 스테이징 검증 | 1~2주 | 부하/보안/회귀 테스트 | 오픈 체크리스트 100% 통과 |
| 5단계: 소규모 오픈 | 1주 | 제한 인원 공개 후 안정화 | 치명 이슈 없음, 지표 안정 |
| 6단계: 정식 확장 | 지속 | 점진적 트래픽 확대/콘텐츠 배포 | 주간 운영 리포트 정상 |

---

## 5. 오픈 전 체크리스트

- [ ] 로그인/회원가입/세션 만료 흐름 정상 동작
- [ ] 저장/로드 충돌 처리(중복 요청, 네트워크 실패) 구현
- [ ] 핵심 재화 로직 서버 검증 적용
- [ ] 에러 추적/알람 채널 연결
- [ ] 일일 백업 + 복구 리허설 완료
- [ ] 약관/개인정보 처리방침/문의 채널 준비
- [ ] 스테이징 테스트 리포트 승인

---

## 6. 리스크와 대응

- **치트/비정상 재화 증가**
  - 대응: 서버 검증, 이상치 탐지, 운영툴 즉시 회수 기능
- **데이터 마이그레이션 실패**
  - 대응: 버전별 백업, 단계적 롤아웃, 실패 시 이전 버전 복구
- **오픈 직후 트래픽 급증**
  - 대응: 큐잉, 캐시, 오토스케일 정책 및 임시 점검 모드
- **배포 후 장애**
  - 대응: 롤백 스크립트, 장애 대응 매뉴얼, 온콜 체계

---

## 7. 즉시 실행 Task (우선순위)

1. 서버 저장 스키마 초안 작성 (유저/인벤/재화/진행도/성물 레벨)
2. 인증 방식 확정 (세션 or JWT) 및 보안 정책 명시
3. `saveDataVersion` 필드와 마이그레이션 엔트리 설계
4. 모니터링 스택 선정 (에러 추적/메트릭/로그)
5. 스테이징 환경 구성 및 배포 자동화 초안
