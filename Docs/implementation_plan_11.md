# implementation_plan_11: 데이터 백업 고도화 1차

## 1) 배경
- 현재 백업은 사용자당 단일 클라우드 미러(`syncToCloud`, `restoreFromCloud`) 구조다.
- 실수로 덮어쓰기하면 이전 상태를 되돌리기 어렵고, 백업 시점 선택도 불가능하다.

## 2) 목표
- 백업 슬롯(1~3)을 제공해 복수 시점 저장/복원을 가능하게 한다.
- 업로드/복원 시 슬롯 선택을 강제해 오작동을 줄인다.
- 현재 로컬스토리지 기반 아키텍처를 유지하면서 서버 어댑터 확장성을 확보한다.

## 3) 설계 원칙
- 기존 API 호환을 깨지 않기 위해 기존 메서드는 유지하고 슬롯 메서드를 추가한다.
- 슬롯 메타데이터(존재 여부/저장 시간)를 노출해 사용자가 안전하게 선택하도록 한다.
- UI는 최소 변경(설정 패널 버튼 재사용 + prompt)으로 1차 적용한다.

## 4) 구현 범위 (1차)
- `js/storage.js`
  - `getCloudSlotKey(slot)` 추가
  - `syncToCloudSlot(state, slot)` 추가
  - `restoreFromCloudSlot(slot)` 추가
  - `listCloudBackups()` 추가
  - `syncToCloud` / `restoreFromCloud`는 슬롯 1로 위임
- `game.js`
  - `syncBackup(isUpload)` 실행 시 슬롯 선택 prompt 추가
  - 선택 슬롯 기준 업로드/복원 수행

## 5) 기대 효과
- 백업을 3개 시점으로 분리하여 덮어쓰기 리스크를 줄인다.
- 저장 시각 기반으로 사용자 판단이 쉬워진다.
- 추후 서버 백업(Firebase/Supabase) 전환 시 슬롯 인터페이스 재사용 가능.

## 6) 후속 과제 (2차)
- 설정 모달 내 백업 슬롯 UI(카드형 리스트) 추가
- 백업 삭제/이름 지정/자동 순환(최근 N개) 기능
- 백업 데이터 무결성 체크섬(해시) 추가
