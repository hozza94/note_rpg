# 📖 Basileia 구현 계획서 #2: 핵심 엔진 고도화 및 시스템 확립

본 계획서는 Phase 1의 마무리와 Phase 2의 핵심 엔진 기능을 구체화하고 구현하기 위한 전략을 담고 있습니다.

## 🎯 목표
1.  **시스템 구체화**: `features.md`를 통해 게임의 모든 수치적 공식과 규칙을 명문화함.
2.  **데이터 무결성 확보**: `storage.js`를 고도화하여 세이브 데이터 유실을 방지하고 확장성을 확보함.
3.  **인벤토리 시스템 구축**: 아이템의 획득, 관리, 장착의 기반이 되는 클래스를 독립적으로 구현함.
4.  **엔진 통합**: 고도화된 시스템들을 `game.js`에 적용하여 안정적인 게임 플레이 환경 조성.

## ⚔️ 사용자 리뷰 필요 사항 (User Review Required)

> [!IMPORTANT]
> 1. **스탯 분배 방식**: 레벨업 시 자동으로 오르는 기존 방식에서 포인트를 직접 투자하는 방식으로 변경할 예정입니다. 이에 따른 UI 추가가 필요합니다.
> 2. **세이브 슬롯**: 우선 단일 슬롯(Auto-save) 체제를 유지하되, 코드 레벨에서는 다중 슬롯 대응이 가능하도록 `StorageManager`를 설계하겠습니다.
> 3. **인벤토리 제한**: 가방의 크기(슬롯 제한)를 둘까요, 아니면 무제한으로 가져갈 수 있게 할까요?

### 2. 핵심 엔진 고도화 (Phase 2)

#### [MODIFY] [storage.js](file:///Users/nk/git/note_rpg/js/storage.js)
- **데이터 검증**: 로드 시 데이터 변조 여부나 버전 호환성을 체크하는 로직 추가.
- **백업 시스템**: 저장 실패 시 이전 데이터를 복구할 수 있는 세이프가드 구축.
- **추상화 강화**: 나중에 Firebase나 Supabase로 쉽게 갈아탈 수 있도록 인터페이스 규격화.

#### [NEW] [inventory.js](file:///Users/nk/git/note_rpg/js/inventory.js)
- **`InventoryManager` 클래스**:
    - `addItem(itemId, count)`: 아이템 중첩 및 신규 획득 처리.
    - `removeItem(itemId, count)`: 아이템 소모 처리.
    - `useItem(itemId)`: 물약 사용이나 장비 장착 이벤트 발생.
    - `sort()`: 등급별/이름별 정렬 기능.

#### [MODIFY] [game.js](file:///Users/nk/git/note_rpg/game.js)
- **인벤토리 클래스 통합**: 기존의 단순 배열 방식에서 `InventoryManager` 인스턴스 사용 방식으로 변경.
- **드랍 시스템 연동**: 전투 승리 시 `calculateDrops` 로직을 정교화하여 확률형 보상 지급.
- **상태 업데이트**: 인벤토리 변경 시 UI 리렌더링 최적화.
